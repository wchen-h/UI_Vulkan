# 补充测试方案：SDR 颜色亮度全覆盖

> 补充自 `tests/TEST_DESIGN.md`（主观匹配实验）。本文档定义一套**系统性的纯色测试素材**，
> 用于覆盖"所有可能出现的 SDR 颜色亮度区间"，而非现有 12 个任意游戏 UI 裁剪。

---

## 1. 目标与约束

| 项 | 值 |
|----|----|
| 目标 | 测试尽可能覆盖所有 SDR 颜色的亮度区间 |
| SDR paperwhite 上限 | **500 nit**（当前代码硬编码 350，见 §7） |
| HDR 背景峰值 | **1600 nit**（当前 BG Nit 滑条 max=4000，已覆盖，无需改） |
| 参照 | SDR 窗口固定显示纯色 UI，HDR 窗口匹配主观亮度/色彩 |

现有测试用 `pic/cropped_images/*_rgb_*.png`（12 个游戏 UI 裁剪），其颜色亮度分布不系统，
无法保证覆盖；且纯饱和色有亮度上限（见 §2），无法用"任意 RGB 比例"覆盖完整亮度轴。

---

## 2. 覆盖原理：亮度轴 × 色度轴

任意 SDR 颜色由两个正交维度决定：

- **明度（luminance）**：`Y = 0.2126·R + 0.7152·G + 0.0722·B`（BT.709 相对亮度），范围 `[0, paperwhite]`。
- **色度（chroma）**：RGB 的比例关系；越饱和，`Y` 相对最大分量的比值越小，亮度上限越低。

饱和色亮度上限（BT.709 相对亮度 × paperwhite）：

| 颜色 | RGB | 相对亮度 Y | @350 nit | @500 nit |
|------|-----|:----------:|:--------:|:--------:|
| 纯红 R | (255,0,0) | 0.2126 | 74 nit | 106 nit |
| 纯绿 G | (0,255,0) | 0.7152 | 250 nit | 358 nit |
| 纯蓝 B | (0,0,255) | 0.0722 | 25 nit | 36 nit |
| 纯青 C | (0,255,255) | 0.7874 | 276 nit | 394 nit |
| 纯品红 M | (255,0,255) | 0.2848 | 100 nit | 142 nit |
| 纯黄 Y | (255,255,0) | 0.9278 | 325 nit | 464 nit |

**结论**：纯饱和色**无法**在任意亮度下显示，只能测其**上限锚点**；完整的明度轴必须用**中性灰阶梯**
（R=G=B，亮度从 0 到 paperwhite 全程可调）覆盖。两者合起来即为"灰阶梯（明度）+ 色度锚点（饱和色）"的全覆盖方案。

---

## 3. 灰阶梯（achromatic，R=G=B）

覆盖 `[0, 500]` nit 完整明度轴。sRGB byte 按 paperwhite=500 反算（`byte = round(inv_sRGB(nit/500)·255)`）。

| 目标亮度 | 说明 | sRGB byte (R=G=B) | 实际亮度 @500 |
|:--------:|------|:-----------------:|:------------:|
| 0 nit | 纯黑 | 0 | 0.0 nit |
| 50 nit | | 89 | 49.9 nit |
| 90 nit | 18% 灰（线性 0.18，同现有 BG_GRAY） | 118 | 90.6 nit |
| 100 nit | | 124 | 100.8 nit |
| 150 nit | | 149 | 150.3 nit |
| 200 nit | | 170 | 201.0 nit |
| 250 nit | 线性 0.5 | 188 | 251.4 nit |
| 300 nit | | 203 | 298.6 nit |
| 350 nit | | 218 | 350.6 nit |
| 400 nit | | 231 | 399.6 nit |
| 450 nit | | 243 | 448.1 nit |
| 500 nit | 纯白 | 255 | 500.0 nit |

> 说明：18% 灰的 sRGB byte 恒为 118（对应线性 0.18），与 paperwhite 无关；其 nit 值随 paperwhite 变
> （350→63 nit，500→90 nit）。其余灰阶 byte 是**按 paperwhite=500 反算**的；若最终仍用 350，
> 需按 §7 的表重算。建议统一在 500 下生成，测试时再按需换算。

**素材命名**：`t_rgb_gray_000.png … t_rgb_gray_500.png`（对应 alpha 素材 `t_alpha_gray_*.png`，
与现有 `t_rgb_black.png` 等命名一致，便于 `loadAssets()` 自动成对加载）。

---

## 4. 色度锚点（chroma anchors）

在灰阶梯之外，用纯饱和原色/二次色锚定色度边角（各取其亮度上限，亮度值由 §2 决定）：

| 锚点 | RGB | 亮度上限 @500 |
|------|-----|:------------:|
| 纯红 | (255,0,0) | 106 nit |
| 纯绿 | (0,255,0) | 358 nit |
| 纯蓝 | (0,0,255) | 36 nit |
| 纯青 | (0,255,255) | 394 nit |
| 纯品红 | (255,0,255) | 142 nit |
| 纯黄 | (255,255,0) | 464 nit |

可选：各锚点的**半饱和**版本（如 (255,128,0) 之类），用于中间色度区域验证——如需要再补，
不阻塞主方案。

**素材命名**：`t_rgb_red / t_rgb_green / t_rgb_blue / t_rgb_cyan / t_rgb_magenta / t_rgb_yellow`
（对应 `t_alpha_*`）。

> 现有 `t_rgb_green / t_rgb_redorange / t_rgb_bluepurple / t_rgb_neutral / t_rgb_black / t_rgb_white`
> 已是部分锚点，本方案补齐纯蓝/纯青/纯品红/纯黄并统一命名。

- 目标覆盖到 **1600 nit**。
- 现有 `hdr_app.cpp` 中 `maxNit_ = 4000`，BG Nit 滑条 `DragInt(..., 0, maxNit_)` 已覆盖，**无需改动**。

## 6. 测试矩阵

沿用 TEST_DESIGN.md 的三层嵌套，仅替换/扩充 UI 素材：

| 层级 | 变量 | 取值 | 组数 |
|------|------|------|------|
| Layer 1 | SDR_UI_Alpha | 0.1 ~ 1.0，步长 0.1 | 10 |
| Layer 2 | HDR_BG_Nit | 0 ~ 1600（建议 50~1600 步长 50） | ~32 |
| Layer 3 | UI 素材 | 灰阶梯 12 + 色度锚点 6 = 18（可再 +半饱和） | 18 |

> 灰阶梯素材本身 alpha 全程为 1（纯色矩形），"SDR_UI_Alpha" 维度对灰阶梯/锚点测试意义有限，
> 可对纯色素材**只测 alpha=1**，从而显著减少测试点（纯色素材不涉及半透明混合）。
> 半透明混合的 alpha 维度继续由现有 12 个游戏 UI 覆盖。

建议的**纯色素材精简矩阵**（alpha 固定 1）：

- 灰阶梯 12 × HDR_BG_Nit（50~1600，步长 50 = 32 点）= 384
- 色度锚点 6 × HDR_BG_Nit 32 = 192
- 合计 ~576 个测试点（远小于现有 2400，且覆盖更系统）

---

## 7. 代码 / 资产改动量评估

| 改动 | 位置 | 类型 | 量级 |
|------|------|------|------|
| 灰阶梯 + 色度锚点 PNG 素材 | 新增 `t_rgb_*.png` / `t_alpha_*.png` | **Python 脚本生成**（PIL） | ~50 行，**零 C++ 改动**（`loadAssets()` 自动成对加载） |
| SDR paperwhite 350→500 | `src/common.h:18` + `shaders/hdr_ui.frag:28` | C++ 常量 + shader 常量 | **2 处常量改动** + rebuild |
| 测试数据 CSV | 扩展 `tests/generate_test_grid.py` 或新脚本 | Python | ~30 行 |
| HDR BG Nit 范围 | 无需改动（maxNit_=4000 已覆盖 1600） | — | 0 |

**结论：代码改动量很小。** 核心渲染管线（sRGB→linear→BT.2020→PQ→YCbCr→Y-Scale）**零改动**；
主体是"生成 PNG 素材 + 生成 CSV"两个 Python 脚本（可在任意机器完成，无需 HDR 监视器）；
唯一需要编译验证的是 `PAPER_WHITE_NIT` 的 2 处常量改动。

> 若最终不升 paperwhite（保持 350），则连这 2 处常量改动也可省掉，只需重算 §3 的灰阶 byte 表
> （按 350 反算）并生成对应 PNG 即可。
